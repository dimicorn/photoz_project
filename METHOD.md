# Методика верификатора: kNN photo-z

## Замысел

Верифицировать корректность расчёта фото-красных смещений методом k ближайших соседей
на выборках Happy (Beck et al. 2017). Обучающая выборка — Happy A; проверочные — B, C, D.

Верификатор состоит из трёх модулей:
1. `test_photoz_properties.py` — 7 свойств kNN photo-z (выпуклость, согласованность, тип агрегации)
2. `test_data_contract.py` — 9 правил договора о схеме данных
3. `test_metrics_consistency.py` — 6 проверок согласованности метрик

## Постановка

**Что меняется:** версия кода `src/photoz.py` (внесённые ошибки для демонстрации).
**Что фиксируется:** обучающая выборка Happy A, проверочные B/C/D, k=10, евклидово
расстояние по feat1..feat5, photo-z = среднее z_spec соседей.
**Что измеряется:** корректность предсказаний, согласованность метрик, целостность данных.

## Данные

- `data/raw/happy_A.txt` — 74 950 строк, обучающая выборка.
- `data/raw/happy_B.txt` — 74 900 строк, проверочная, то же распределение.
- `data/raw/happy_C.txt` — 60 315 строк, проверочная, больше ошибок фотометрии.
- `data/raw/happy_D.txt` — 74 642 строки, проверочная, смещена к тусклым/красным.

Формат: пробельно-разделённый, заголовок `# id mag_r u-g g-r r-i i-z z_spec feat1 feat2 feat3 feat4 feat5`.
Столбцы: 0=id, 1=mag_r, 2=u-g, 3=g-r, 4=r-i, 5=i-z, 6=z_spec, 7-11=feat1..feat5.

## Договор о схеме данных

| Столбец | Тип | Диапазон | Примечание |
|---|---|---|---|
| id | int | > 0 | SDSS ObjID, дубликаты возможны |
| mag_r | float | 8..31 | AB mag |
| u-g, g-r, r-i, i-z | float | −16..17 | цвета, mag |
| z_spec | float | 0..5 | спектроскопическое красное смещение |
| feat1..feat5 | float | −70..70 | стандартизованные mag_r и цвета |

## Правило принятия

Все тесты должны пройти:

```bash
.venv/bin/python checks_hw2/test_photoz_properties.py && \
.venv/bin/python checks_hw2/test_data_contract.py && \
.venv/bin/python checks_hw2/test_metrics_consistency.py
```

Код 0 — принято. 22 теста: 7 свойств + 9 договоров + 6 согласованности.

## План эксперимента

1. **Smoke-тест:** запустить все 22 теста на текущем коде — все должны пройти.
2. **Внести ошибку:** сдвинуть FEATS с `slice(7, 12)` на `slice(6, 11)`.
3. **Пересчитать:** запустить `src/photoz.py` — предсказания изменятся.
4. **Проверить:** запустить верификатор — поймать ошибку.
5. **Исправить:** вернуть `slice(7, 12)`, пересчитать, убедиться что всё прошло.

## Ограничения

- Верификатор не проверяет физическую корректность photo-z (это задача астрофизики).
- Верификатор не проверяет качество модели (это задача эксперимента).
- Верификатор не проверяет репрезентативность обучающей выборки (это задача гипотезы проекта).
- Верификатор не проверяет статистическую значимость различий между выборками B, C, D.
- Верификатор не проверяет корректность стандартизации feat1..feat5 (предполагается что она верна).
- Верификатор не проверяет корректность расчёта dz = (z_phot − z_spec)/(1 + z_spec) — это проверяется косвенно через согласованность метрик.
